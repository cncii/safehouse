# S10 残余风险 · 合规说明（引擎日志绝对路径）

**日期**：2026-10-22｜**归属**：技术架构（tech-architect）｜**协作**：QA 自行调整 `pii_probe` 判据口径，本文件不直连 QA
**上游**：`docs/交接项_战斗组致架构QA_引擎日志绝对路径_S10残余风险.md`、架构 §6.3、QA 自查表 A9 / S10

## 一、现象
Godot 引擎在脚本 `Parse Error` / `Failed to load script` 报错时，会在 `user://logs/` 写入含**脚本绝对路径**的错误行，例如：

```
USER SCRIPT ERROR: Parse Error: Identifier "Steam" not declared in the current scope.
   at: GDScript::reload (C:/Users/CQY/AppData/Local/Temp/pck_matrix_6xtkyc_g/F_addons_plus_path_env/_probe.gd:5)
```

命中 `C:/Users/CQY/...` —— 完整 Windows 用户目录。

## 二、范围界定（关键）

| 来源 | 是否含 PII | 说明 |
|---|---|---|
| 游戏自身 `Logger.log()` | ✅ **0 行** | 结构化日志（字段 `sys=/ev=/path=/delta=/why=`）从不写绝对路径，PII 契约未破 |
| Godot 引擎错误输出 | ⚠ **会写** | 引擎在脚本加载失败时报错带脚本绝对路径 |

→ 泄漏源是**引擎**，不是业务代码（`logger.gd` 完全干净）。

## 三、根因
仅当脚本加载失败（资源损坏 / 版本错配 / 运行时符号缺失）才触发。正常运行的工程无 Parse Error，故平时不可见。

## 四、定性结论

**「引擎行为，非代码缺陷」。**

- 我方 PII 契约（禁止 `globalize_path()` 结果、绝对路径、用户名等）由业务日志 `logger.gd` 严格守住，**未破**。
- 绝对路径出现在日志中，责任在引擎，不在本项目代码可控范围，因此**不计入我方 PII 泄漏**。

## 五、缓解措施（A + B）

**A · 契约 + 说明（架构侧）**
- `logger.gd` 头注释补例外条款（明确「引擎错误输出不计入 PII 泄漏」）。
- 架构 §6.3 增 PII 契约例外说明，并指向本文件。
- QA `pii_probe` 判据口径对齐：**只扫 `sys=` 开头的结构化行**；另立一条独立断言记录「引擎错误行含绝对路径」为**已知例外**，避免门禁在任意脚本报错的机器上偶发红。

**B · 构建步骤（构建侧）**
- 导出 / CI 流程第一步清空 `user://logs/` 目录（`tools/export.ps1` 的 `Clear-LogDir`），成本极低。
- 日志不随包发布、不进入崩溃报告自动收集范围。

## 六、残余风险与接受
若玩家本机某脚本解析失败，引擎仍会在**该玩家本机** `user://logs/` 写绝对路径。但：
1. 我方日志扫描口径已排除该来源（QA 只扫 `sys=` 行）；
2. 日志不上传包、不进崩溃报告自动收集（B 步骤 + 客服收集流程约定）；
3. 该路径仅含玩家自身用户名，无第三方 PII。

→ **接受**，不视为我方 PII 泄漏；列入已知例外，不重复投入。

## 七、与 QA 协作
QA 自行调整 `pii_probe` 判据口径（只扫 `sys=` 行 + 独立记录引擎例外），本架构不直连 QA，各自交付。
