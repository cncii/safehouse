## 1. 工程硬约束（来自架构，美术组不可协商）

| 项 | 值 | 出处 | 对美术的直接后果 |
|---|---|---|---|

## 2. 六条风格条款（逐条是拒收理由）

### S1 · 16px 像素网格

- **规定**：图块严格 16×16；所有 PNG 的**宽高必须是 16 的整数倍**。
- **为什么是 16 不是 24/32**：① 与 TileMap 图块尺寸同源，混用 24px 素材会在 TileMap 里产生半格错位；② 640×360 ÷ 16 = 40×22.5 格，是 UI 对齐的唯一栅格；③ 16 的倍数在 1×~6× 整数缩放全部保持像素对齐。
- ✅ 合规：`16×16`、`16×24`、`16×32`、`32×32`、`192×112`
- ❌ 拒收：`24×24`、`20×20`、`100×100`、`32×1`（**注意：连调色板 LUT 图都受此约束**，见 §7.3 第 3 条）
- **机器验收**：A1（`tools/check_assets.py`）

### S2 · 单素材 ≤ 32 色，全项目统一 Target Palette

- **规定**：单文件唯一色数 ≤ 32；所有素材最终映射到统一 target palette。
- **Target Palette = DB32（32 色）**，色值见 §3，**冻结，不得增删**。
- 超色素材**先过 `palette_map.gdshader`**，映射后仍超 32 色或出现明显色断层 → 拒收。
- **机器验收**：A4
- **为什么用统一 palette 而不是"每人管好自己的色"**：本项目美术走素材包采购（架构 R6），来源必然杂。**三个来源的素材摆在一起出戏**是本项目美术的头号风险——人眼先感知的是"颜色不像一套"，其次才是画风。

### S3 · 左上光源 + 顶视 3/4 角度

- **规定**：所有实体/物件/图块的光源方向为**左上 45°**（左上亮、右下暗）；视角为 **RPG 式俯视 3/4**（能看到物体的顶面和正面，不能是纯侧视、不能是正交顶视）。
- **为什么这条最致命**：光源方向相反的素材**并排放置**时，人眼 0.2 秒就能察觉违和，且**没有任何自动化工具能查**——它是人工验收的头号对象。
- **人工验收**：截图里放两个不同来源的精灵并排，视线从上一个滑到下一个，感觉"哪里怪"就是这条没过。
- 参考 litmus test：右上角应该有**高光**，右下角应该有**投影**。

### S4 · 1px 深色描边，有无描边不混用

- **规定**：实体与物件一律 **1px 深色描边**；描边色取 target palette 的 `#222034`（Valhalla）。**禁止在同一个类目里混用有描边和无描边两套风格**。
- **为什么不是纯黑**：纯黑 `#000000` 描边在暗背景下会糊成一团，`#222034` 保留同样视觉重量但在暗场景里仍有区分度；且它是 DB32 的内置色，不增加色数。
- 例外（**写入素材备注**：`no_outline: true`）：UI 底板内部允许无描边，但 UI 件整体外缘必须有描边。

### S5 · 立绘单独规则

| 项 | 规定 | 依据 |
|---|---|---|
| 画布 | **192×256**（16 的倍数） | 事件 CG 半身构图；占屏高 71%，留出对话框空间 |
| 裁切线 | **统一在胸口以上**，头顶留 16px，底部对齐 y=240 | S5 原条款「统一半身裁切线」；不一帧一个样 |
| 背景 | **统一透明**，不允许自带背景板/渐变背景 | 事件 CG 要叠场景，带背景=无法复用 |
| 描边 | 1px `#222034`（同 S4） | 与场景风格同源 |
| 状态数 | MVP 先做 2 态（neutral / injured），表情族后续按 §批次走 | 控内容量，防 R1 |

### S6 · 中文字体必须含 license 文件

- **规定**：任何嵌入分发的中文像素字体，必须随包附带**原始 license 文件**，并在 `docs/asset_sourcing.md` 登记。
- **缺 license = 一票否决**（法务风险，Steam 上架会查）。
- **已定案（2026-10-21 老板核准）**：**Fusion Pixel Font（缝合像素字体）12px**，SIL OFL 1.1，作者 TakWolf。
  - 落地：`assets/fonts/font_fusion_pixel_12px_zh_hans.ttf` / `..._zh_tw.ttf`（各约 6.8 MB，两地区各一份）
  - 授权：`assets/_licenses/` 下 **4 份**——本体 + 三个上游（Ark Pixel / Cubic 11 / Galmuri），全部 OFL 1.1
  - ⚠ 它是**缝合体**：把三个像素字体缝在一起补字，所以授权链是 4 份、不是 1 份。少放一份就是授权不全
  - 覆盖实测：**37415 个码位**，自带完整 ASCII / 数字 / 全角标点，**不需要额外装拉丁字体**
- **字号**：正文 / HUD / 数值 **12px**；标题 / 弹窗标题 **16px**（与 16px 图块栅格同源）；
  10px 仅限极窄角标且需实测。12px 是 640×360 下中文可读下限，10px 笔画会糊。
- **选型依据（实测数据，不是推荐意见）**：原候选 Ark Pixel 被数据淘汰——

  | 字体 | 当前 `strings.csv`（143 字） | GB2312 一级字（3716 字） |
  |---|---|---|
  | Ark Pixel | 缺 5：击 据 药 避 脏 / 擊 據 避 髒 | **缺 147（96.0%）** |
  | **Fusion Pixel** | **0 缺** | **0 缺（100%）** |

  Ark 缺的字含「热、燃、餐、窗、聚、紧、酸、药、避、警」——末日生存题材的高频字。
  手补 147 个像素字形不现实，故**不进包**。
- **验证方式**：`python tools/check_font_coverage.py --csv data/locale/strings.csv --font <ttf>`
  （退出码非 0 = 有缺字）。`strings.csv` 每次定稿后重跑一次。

### 3.1 UI 专用子集（**只用这 6 色**，理由见下）

| 用途 | Hex | 为什么选它 |
|---|---|---|
| UI 描边 | `#222034` | 与 S4 实体描边同源，UI 与场景视觉粘连感一致 |
| 底板主色 | `#323c39` | 深灰绿，末日废土调性；比纯黑通透，不会压死文字 |
| 底板内凹 | `#595652` | 比主色亮一档，做按下/禁用态不需要新增色 |
| 面板高光边 | `#847e87` | 左上光源（S3）在 UI 上的落点：左上 1px 亮，右下 1px 暗 |
| 文本主色 | `#eec39a` | Pancho，暖白；纯白 `#ffffff` 留给高亮强调，避免正文过曝 |
| 强调/告警 | `#fbf236` | Golden fizz，饱和度最高，做 ⚠ 缺口提示的唯一强调色 |

**为什么限制到 6 色**：UI 是全屏常驻物。**UI 每多一个色，玩家眼睛就多一个停留点**，四条状态条 + 链面板同屏时，色彩超过 6 色就开始抢夺本该留给场景的注意力。这条同时也是 A4（≤32 色）的安全垫——6 色留了 26 色的容错空间给图标与帧动画。

## 4. UI 件规格（美术组产出，表现组接入）

> 分工边界：《任务书_美术组_资产.md》§2 明确——**美术出 UI 件素材，界面布局归表现组（包 D）**。本节所有数字是**素材本身的规格**，不是布局。

### 4.1 尺寸表

全部尺寸 = 16 的整数倍（S1），在 640×360 画布下的占比见依据列。

| 件 | 尺寸（px） | 占屏（宽/高） | 为什么是这个数 |
|---|---|---|---|
| `ui_bar_frame` | **112×16**（可见 112×14） | 17.5% / 4.4% | **宽度必须等于包 D 的 `HudStyle.BAR_W = 112`**，否则底板比控件宽、左右各溢出一截（初版出 128 就多出 16px）。112 = 7×16，恰好也是 A1 的合法值。故**尺寸由接入方常量决定，不由美术自选** |
| `ui_bar_fill` | **112×16**（可见带 108×10 @ 2,3） | — | A1 要求**文件**宽高都是 16 倍数，图内可见带多宽是自由的 → 凹槽 108×10 让四边边框统一为 2px。**初版误以为可见带也得是 16 倍数**，把槽压到 104，结果左右剩 4px、上下剩 2px，四条边不成比例 |
| `ui_panel_dialog` | **192×112** | 30.0% / 31.1% | 192 是 640 的 30%，横向还能放一列内容；112 高够 5 行 16px 文本 |
| `ui_panel_small` | **96×64** | 15.0% / 17.8% | 链状态面板的单卡；同屏可排 4 张（建造三行 UI 用） |
| `ui_btn_base` | **96×32** | 15.0% / 8.9% | 高度 32 是"能放下 16px 字+上下各 8px 留白"的最小值 |
| `ui_slot_item` | **32×32** | 5.0% / 8.9% | 背包格；一行 10 格 × 8 行 = 满屏背包 |
| `ui_palette_db32` | **32×16** | — | 色板 LUT 图，供 `palette_map.gdshader` 采样（见 §7.3 第 3 条） |

### 4.2 九宫格边界（**四个具名值**）

> ⚠️ 写"四个具名值"而不是位置序列——Unity 是左下右上、Godot/Unreal 是左上右下、**Cocos 是左右上下**，写成序列必然接反。

| 件 | left | top | right | bottom | 依据 |
|---|---|---|---|---|---|
| `ui_panel_dialog` | 8 | 8 | 8 | 8 | 圆角 r=4 + 描边 1 = 5 → 上取 8（保持 16 网格的 1/2，位置对齐不产生半像素） |
| `ui_panel_small` | 8 | 8 | 8 | 8 | 同上 |
| `ui_bar_frame` | — | — | — | — | **不需要九宫格**：可见尺寸 112×14 与控件尺寸完全相同，永不拉伸。填任何边距只会引入"拉伸后才生效"的伪参数 |
| `ui_bar_fill` | — | — | — | — | 同上，**不拉伸**。进度靠**裁切宽度**实现（见 §4.7 组合规则表），不是缩放——缩放会把像素拉成非整数宽度 |
| `ui_btn_base` | 8 | 8 | 8 | 8 | 通用按钮，圆角 r=4 |
| `ui_slot_item` | 4 | 4 | 4 | 4 | 32×32 小格，圆角 r=2 |

**Godot 4.3 落地**（`NinePatchRect` 节点）：

```
Texture          = res://assets/sprites/ui/ui_panel_dialog.png
patch_margin_left   = 8
patch_margin_top    = 8
patch_margin_right  = 8
patch_margin_bottom = 8
```

> 好消息：Godot 的九宫格参数绑在**节点**上，不像 Cocos 绑死在 SpriteFrame 资源上。**同一个底板要两种边界时不需要出两张图**——但我们仍然只为每件出一个边界（上表），避免表现组在不同界面用了不同拉伸导致视觉不一。

**通用后处理（所有 UI 件）**：
- 圆角必须是**像素阶梯**（硬边 2 级台阶），**禁止平滑圆角**——平滑圆角一条弧就会产生 20+ 中间色，直接撞破 A4。

### 4.3 色数与叠色规则

- 单个 UI 件 ≤ **6 色**（§3.1 子集）+ 完全透明。
- **禁止**：渐变（即使 2 色渐变，中间插值也会造出几十种色）、外发光模糊、半透明羽化边缘、`.9.png` 式的黑边标记。
- Alpha：只允许 0 或 255 两个值，**不做中间值**。素材自带的半透明边缘用 `palette_map.gdshader` 的 `alpha_cut` 二值化清掉。
- 导出：**索引色 PNG-8 + 透明索引**，不要用 32bit RGBA 直接导出（包体预算 §7.2 #9）。

### 4.4 状态矩阵（每个可交互元素必须出全）

| 件 | 常态 | 悬停 | 按下 | 禁用 | 选中 |
|---|---|---|---|---|---|
| `ui_btn_base` | `_normal` | `_hover` | `_pressed` | `_disabled` | `_selected` |
| `ui_slot_item` | `_normal` | `_hover` | — | — | `_selected` |
| `ui_bar_frame` | 只出常态（数值变化走 fill 宽度，不换底板） | | | | |

> **为什么必须有 hover**：project.godot 的输入映射全是键鼠。**缺 hover 态的键鼠界面是最常见的返工点**——玩家点下去之前没有任何反馈。
> 禁用态用 `#595652`（底板内凹色）压暗 + 去掉描边高光，不加新色。

### 4.5 命名与版本号

**机器验收：A3**（正则 `^(char|enemy|item|tile|ui|portrait|font)_[a-z0-9]+(_[a-z0-9]+)*\.png$`）

✅ 合规：
```
ui_bar_frame.png                 ui_btn_base_normal.png
ui_panel_dialog.png              ui_slot_item_selected.png
ui_palette_db32.png              ui_bar_fill_v1.png
```

❌ **会被 A3 拒收**（见 §7.3）：
```
ui_panel_dialog@v1.png     → @ 非法字符
ui_panel_dialog.9.png      → 多余的 "." 
atlas_ui_panels.png        → 前缀必须是 ui_，不能是 atlas_
ui_alert-icon.png          → 连字符非法，用下划线
ui_Frame.PNG               → 大写后缀 + 大写字符
```

**版本号规范**：用 `_v1` 而不是 `@v1`，写在文件名最后一段（`ui_bar_fill_v1.png`）。改版本号不算改名，但**改动命名必须提前通知表现组（包 D）**——命名即契约（任务书 §7）。

### 4.6 图集分组与命名

> ⚠️ **图集文件名也必须过 A3**：前缀必须是 `ui_`，所以是 `ui_atlas_panels.png`，**不是** `atlas_ui_panels.png`。

| 图集 | 尺寸预算 | 内容 | 何时加载 |
|---|---|---|---|
| `ui_atlas_panels.png` | 512×512 | dialog / small panel / bar_frame / slot | 常驻（HUD 要用） |
| `ui_atlas_buttons.png` | 256×256 | 按钮五态 × 3 尺寸 | 常驻 |
| `ui_atlas_icons_ui.png` | 256×256 | 链图标、设置图标、状态图标 | 常驻 |
| `ui_atlas_icons_item.png` | 512×512 | 物品图标 | 背包打开时 |
| `ui_atlas_portraits.png` | 512×512 | 事件立绘（192×256，2 张一行 → 8 张满） | 事件 CG 时 |

**分组依据**：按**使用时机**分组，而不是按美术类别——同一时刻上屏的精灵才能合批（Draw Call 预算 #5）。常驻三类合起来 VRAM 约 1.1 MB（索引色），对 200 MB 预算毫无压力。

### 4.7 交给表现组（包 D）的接口契约

1. 素材一律落 `assets/sprites/ui/`，命名按 §4.5；**命名即契约，改名提前通知**。
2. 所有 UI 件**不含任何文字**——文字一律 Godot 内 `Label` 渲染 + `Localize.text()`。理由：多语言无法替换 + 字体侵权。
3. 九宫格参数一律从 §4.2 具名值表读，**不要从图里猜**。
4. 颜色一律从 §3.1 / §3.2 取，**不要吸色后手写**。
5. 灰盒（色块）阶段**美术素材不进工程**（任务书 §7）——避免给手感调参制造噪音。`ui_palette_db32.png` 与 shader 属第一批例外（它们不影响场景观感）。

**状态条的组合规则（★ 这张表决定了接入代码怎么写）**：

| 项 | 规则 |
|---|---|
| 合成原点 | `frame` 与 `fill` **都画在控件的 (0,0)**。左右 2px、上下 3px 的偏移全部编码在图内的透明边距里，**接入方不记任何偏移量** |
| 进度 | 靠**裁切 `fill` 的宽度**实现（`draw_texture_rect_region` 的 `src` 宽度 = `2 + round(108 × v/100)`），**不要缩放**——缩放会产生非整数像素宽度，像素边缘发虚 |
| 拉伸 | 两件都**不拉伸**（尺寸与控件一致）。所以九宫格参数对本件无意义（§4.2） |
| 染色 | `fill` 是纯白 `#ffffff`，用 `modulate` 上色。**色值只能取 §3.2 的三档**（见下表）——⚠ `modulate` 在运行期生效，**P1 色板门禁查不到它**（PNG 本身是白的），所以这条只能靠约定，见 §4.7 下方警告 |

| 状态 | 色值 | 触发（包 D `VitalBar._color_for`） |
|---|---|---|
| 正常 | `#6abe30` | `v > 40` |
| 警戒 | `#df7126` | `v ≤ 40` 且 `v > 阈值` |
| 危险 | `#ac3232` | `v ≤ 阈值`（HP/饥饿/水分 25，体力 10） |

> ⚠ **`modulate` 染色是色板门禁的盲区。** `ui_bar_fill.png` 里只有 `#ffffff`，P1 只能确认"白在 DB32 内"；
> 表现组一旦在代码里写 `Color(0.9, 0.2, 0.2)` 这种手调值，**没有任何门禁会红**，但画面已经跑出 DB32。
> 所以染色值必须从本表取，不要自己调。

## 5. palette_map.gdshader 使用说明

**文件**：`assets/shaders/palette_map.gdshader`
**作用**：把不同来源精灵的色板映射到统一 target palette。这是一个 shader 顶 40 小时重绘的手段。

| 参数 | 默认 | 说明 |
|---|---|---|
| `palette_tex` | `ui_palette_db32.png` | 32×16 LUT，第 8 行 32 个像素 = DB32 |
| `mix_strength` | 1.0 | **0 = 原图 / 1 = 完全映射**。做验收对比图时拉它 |
| `outline_color` | `#222034` | **暗部统一色**——低于阈值的像素压成它。这就是契约 S4 那条描边色，把条款变成 shader 行为 |
| `outline_luma` | **0.02** | 低于此亮度的像素视为描边。⚠ 这是 **linear 空间**的值：描边 `#222034` 约 0.017、深棕描边约 0.015、冷蓝描边约 0.008，而正常填充（如 `#323c39`）约 0.041。**误填 0.12 会把大片暗部吞成描边色** |
| `alpha_cut` | 0.5 | 半透明羽化边缘二值化，**杀掉素材自带的抗锯齿脏边** |

> **⚠ 这里踩过一个坑（已实测证伪并修正）**：本 shader 初版把暗部设计成「保护原色、不参与映射」。
> 实测断言直接打红——最近邻映射根本不会抹掉描边，它只把描边换成**各自最接近的暗色**，
> 结果暖色素材保留深棕描边、冷色素材保留冷蓝描边，并排时描边色依然不同，**等于没统一**。
> 改成「暗部强制统一到 `#222034`」后，越界色归零、两张图描边色一致。
> **教训：统一色板的目标是"所有像素都落在 palette 内"，而不是"某些像素不受影响"。**
| `alpha_cut` | 0.5 | 半透明羽化边缘二值化，**杀掉素材自带的抗锯齿脏边** |

**验收方式**（任务书 §4 指定）：两张来源不同的精灵图，把 `mix_strength` 拉到 0 和 1 各截一张，并排放——**看出是两个来源 = 未过；看不出 = 过关**。

**实测记录（2026-10-20，本轮已验证）**：

| 项 | 结果 |
|---|---|
| Godot 4.3 解析 | ✅ **通过**。5 个 uniform 全部识别（`palette_tex` / `mix_strength` / `outline_color` / `outline_luma` / `alpha_cut`），无编译错误，exit=0 |
| 算法验证 | ✅ **通过**。两张不同来源精灵映射后：越界色 **0**、描边同为 `#222034`、羽化边缘被 `alpha_cut` 清掉 178 px |
| 对比图 | `build/art_proof/palette_map_ab_compare.png`（上排原图 / 下排映射后） |
| 验证脚本 | `build/art_proof/check_shader.gd` |
| **GPU 真实渲染** | ❌ **未做，本机不可行**（见下） |

> ⚠ **这张对比图不是 GPU 渲染出来的，是 Python 复刻算法画的。**
> 2026-10-22 实测：`--headless` 下 `RenderingServer` 是 dummy 后端，`frame_post_draw` 永不触发，
> `SubViewport.get_texture()` 拿不到像素——本机没有第二条路能离屏渲染（要真 GPU 输出得起窗口进程）。
>
> 这个限制的实际含义：**如果我对「Godot 采样 sRGB 纹理返回 linear 值」这个前提判断错了，
> Python 复刻会跟着一起错，两张图仍然"符合预期"** —— 这是典型的自洽式假绿。
> 目前能给的证据只有两条，都不到 GPU 级：
> ① shader 被 4.3 完整编译（语法与 uniform 类型无误）；
> ② `.import` 里 `compress/mode=0`、无 mipmap 的 2D sRGB 管线（导入侧配置正确）。
> **真正确认要等第一批真实精灵图接入编辑器时截图**——那时若颜色不对，
> 第一嫌疑是颜色空间，先调 `outline_luma` 与 palette 的 sRGB/linear 处理再动别的。


复现命令：
```
Godot_v4.3-stable_win64_console.exe --headless --path <工程根> -s res://build/art_proof/check_shader.gd
```

> ⚠ **验收时该留意的一条**：映射后整体会**偏暗**。原因是 DB32 的暗色占比高，暖色会被吸到 `#ac3232` 这类暗饱和色。
> 这是 DB32 本身的调性（符合末日废土），**不是 shader 的 bug**。若老板认为"映射完整个变灰了"，
> 正确处置是**换更亮的 palette**，而不是去调 shader 参数。

**工程接入**：放在需要统一风格的 Sprite2D / TileMap 的 `Material` 槽。建议只给**采购来源**的素材挂，自绘素材不挂（省 Draw Call）。

## 7. 验收

### 7.1 机器验收

```powershell
python tools/check_assets.py                  # 验收器（不可改）
python tools/check_palette_conformance.py     # 色板一致性（本表 P1–P4）
```

| 规则 | 判据 |
|---|---|
| A1 | 所有 PNG 宽高是 16 的倍数 |
| A2 | 图集最长边 ≤ 2048 |
| A3 | 命名 = 域前缀 + 小写蛇形 |
| A4 | 单文件 ≤ 32 色 |
| P1 | 可见像素的颜色**严格等于** DB32 某一色（差 1 也算违例） |
| P2 | alpha 只允许 0 或 255 |
| P3 | 单文件可见像素 > 0（空素材不算合规） |
| P4 | 色板 LUT 的颜色集合与 §3.2 冻结表**完全一致** |

⚠ `tools/check_assets.py` **不可修改**（任务书 §3：改它 = 作弊）。

**为什么另起一道 P 而不是改 A4**：A4 只数「有几个颜色」，判不了「这几个颜色是不是 target palette 里的」。
一张 32 色但整张都在 DB32 之外的图，A4 会**直接放行** —— 而「全项目统一 target palette」正是 S2 的后半句。
P1–P4 补的就是这半句，且**不碰验收器**。

### 7.2 人工验收（不可替代）

同屏放**两个来源的精灵并排**截图：**看得出区别 = 未过 palette_map；看不出 = 过关**。
二次验收：光源方向一致性（S3），**这条没有任何工具能查**，只能肉眼。

### 7.3 已发现的四条「验收器 vs UI 惯例」冲突（**美术组必须提前知道**）

> 这四条是逐字读 `tools/check_assets.py` 源码后发现的，会直接导致第一批交付被打回。**每条都给出绕法，且都不需要改验收器。**

| # | 冲突 | 后果 | 绕法 |
|---|---|---|---|
| 1 | A3 正则字符类只有 `[a-z0-9_]` | `@v1` 版本号、连字符 `alert-icon`、多余点 `.9.png` 全部判违例 | 版本号用 **`_v1`**；单词一律下划线；文件名只允许**一个**点 |
| 2 | A4 统计的是 RGBA 唯一色 | 抗锯齿圆角 / 渐变 / 透明羽化**任意一项**都能单独造出 40+ 色 | UI 件一律**像素硬边**（§4.3），色数控制在 6 色以内 |

| 5 | A1 只管 16 倍数，不认"视觉上要薄" | **本文件原稿写的 `ui_bar_fill` 112×8 自己就过不了 A1**（8 不是 16 倍数） | 出 **112×16**，上下各 1px 全透明留白把可见带压到 14px 内（见 §4.1） |
| 6 | **A1 约束的是文件，不是可见带** | 我一度以为可见宽度也得是 16 倍数，把凹槽从 108 压到 104 → 左右各剩 4px、上下剩 2px，四条边不成比例 | 可见带随意（108×10），**只要把文件补到 112×16** |

> 第 5 条是 2026-10-22 真做图时才暴露的：**规格写在纸上不报错，落成文件才报错**。
> 同类风险还有 `HudStyle.BAR_H = 10`（包 D 灰盒期常量）——10 也不是 16 的倍数，
> 换成像素素材时**必须一并改成 16**，否则素材进不去。已写进致包 D 的接口说明。
