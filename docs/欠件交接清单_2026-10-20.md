## 二、必须记住的三条纪律（本轮实证得出）

### 纪律 1 · `--import` 不当验收判据，但归因要准确（已修正一次）

**初判**（主程序）：冷导入有竞态 → 连跑 4 次得 26/28/26/**0**。

**归因修正**（QA 第二轮 + 我的复核）：**冷导入本身是稳定的，0 条那轮是并发造成的。**
三次独立尝试均未复现：QA 在隔离副本连跑 5 轮 = 26/26/26/26/26 逐轮一致；
我在真工程连跑 2 轮 = 各 26 条。真实成因是**当时有另一会话在并发 `rm -rf .godot`**。

| 方式 | 准确的归因 |
|---|---|
| 热导入（`.godot` 存在） | 按 mtime 增量扫描（主程序实测，**未经二次复现**）——仍不当判据 |
| 冷导入 | **并发下**不可用；单人环境实测稳定 26 条 |

**结论方向不变，但注释口径必须改**：`compile_sweep.gd` 文件头现有注释把"连跑 4 轮得 0"
写成冷导入的固有缺陷——**这会让后人误以为单人也不可用，从而不敢用它做交叉验证。**
应改为"并发 `rm -rf .godot` 会导致 0 条假绿"。

**仍以 `compile_sweep.gd` 为判据**，理由与竞态无关：它同步、可自验、结果明确。

### 纪律 2 · 数字服从规则，不是规则服从数字
本轮三次出现"数字对不上"，三次都判**采信实测值、修正上游数字**：
- 架构 Python 复算 `0.4208xx` vs 引擎实测 `0.9441xx` → 结论一致，数字不可引用
  → 由此定：**复算只能定性，定量必须实测**
- QA 预期"变异 3 → A2/A3 同时红" → 实测单一变异做不到，拆成 M3a/M3b 互补覆盖，
  **没有为了数字好看去造复合变异**
- M28-a 修后 31 处而非 36 → 加 `s` 兼容老键必然吃掉所有 `_s` 键；
  **不为把数字凑回 36 而给 `attack_interval_s` 单独开口**

### 纪律 3 · 门禁必须自带正负自检样例，且自检不能是恒真
- 没有 `SELF_CHECK_POSITIVE` / `SELF_CHECK_NEGATIVE` 的门禁**视为未交付**
- `validate_data.py` 的 M1/M3 自检原是「red 非空即 KILLED」，而 M28-a 未注入缺陷时
  red 已非空 → **恒 KILLED，假绿**。已改为「与基线比数量」
- 自检夹具放工程外或内存造，**不许在 `src/` 下留真坏脚本当夹具**

## 四、已知边界（不是缺陷，别重复排查）

1. **`-s` 主脚本的 autoload 标识符问题扫不出来**。`compile_sweep.gd` 每次输出都会明写这句提示。
   `-s` 模式下 `Node._ready()` 不触发 → `Localize._table` / `Rng._salts` 为空，
   空表状态下「缺键回落到 key 本身」照样为真——**这是最容易骗过验收的假绿**，
   QA 已加 A0-4 / B0-4 空跑判负。
2. **`compile_sweep` 依赖 `.godot` 稳定**。扫的时候不要并发 `rm -rf .godot`，
   否则 global class cache 被重建会让 `HudStyle`/`SettingsScreen` 等全局类解析不到。CI 下不会触发。
3. **`String.hash()` 无跨版本保证**。已钉哨兵 `"abc".hash() == 193485963`，
   引擎升级导致哈希变化时这条先红，把静默失效变成显式失败。

## 六、本轮最值得记住的一句话

> 自动化全绿只证明没崩，不证明好用。
> 这轮先后做出三个"权威判据"（热导入、冷导入、compile_sweep v1），**三个都不可信**；
> 加上测试侧两条（运行时报错吞断言、`_ready()` 不触发）与 `F0-b` 空洞判据，
> **六个都是同一个形状：报告说全绿（或全红），实际什么也没证明。**
> 其中两个（`F0-b`、`compile_sweep` v1）还是本轮为修假绿而新造的——
> **修假绿的过程本身会造出新的假绿。**
> 这一轮真正的产出不是修好了两个 core 缺陷，是把六个假判据换成了一个真的。
