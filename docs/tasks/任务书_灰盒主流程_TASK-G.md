# 任务书 · 灰盒主流程接线（TASK-G · P1.5 闭环）

**编号**：TASK-G v1.0（2026-10-22）｜**牵头**：表现组（包 D，场景/入口/HUD）｜**配合**：逻辑组（包 B，系统侧补缺）｜**验收人**：老板（灰盒手感闸门，三方审）
**这一份和前五份不同**：前五份各管一摊，这份只干一件事——**把已经建好的系统串成"能从头玩到尾的一局"**。

## 0. 为什么是现在

五队 DoD 主体达成、门禁 167 条全绿、P0 已修（读档路径已通）。但 boot 自检通过后停在空场景——**没有一根线把系统串起来**。本任务交付后即进入灰盒手感闸门（老板亲玩），**闸门不过不许进资产批量阶段**。

## 1. 一句话目标

冷启动 → 05:00 在安全屋醒来 → 吃喝/看面板 → 总览图选超市出门 → 灰盒搜刮 + 打丧尸 → 18:00 回屋投料/研发 → 跳夜 → 次日 05:00 自动存档 → 第 7 天 20:00 门锁 → 过渡夜 → 阶段 B 七夜（白天经营 + 夜间波次）→ 夜 7 天亮通关。**色块美术、无音效、1 个地点。**

## 3. 分工

| 组 | 干什么 |
|---|---|
| **表现组（牵头）** | 场景搭建与切换（SceneRouter）、极简主菜单、总览图（节点+距离 GH 成本）、玩家角色场景、HUD 三块上屏、通关/死亡画面 |
| **逻辑组（配合）** | location_base 与 `MapSystem.enter_node()` 对接、拾取→`InventorySystem.add()`、研发/建造动作实例化、门禁判定接 `TimeSystem`、阶段 A→B 切换实装（含过渡夜 TRANSITION_NIGHT） |

## 4. 硬约束（违反 = 打回）

1. **全走既有接口**：状态写 `StateStore.apply`、随机 `Rng.hash_at`、结算序 `ResolveOrder`、持续动作 `ContinuousAction`——新状态路径先补 `state_contract.json` 再写代码。
2. **夜间波次必须 WAVE_DRIVEN**（击杀比 + 8 分钟兜底），禁真实时间驱动。
3. **自动配给不许抢先存在**（P1.5 审核项：饿到 0 不进食必须 100±2 s 死亡——M2 已有判据，灰盒实机不得破坏）。
4. **每个耗时动作给可预期时长**（建造/研发前显示剩余 GH）。
5. **零中文字面量** / 门禁 167 条不许回归（每轮提交跑 `tools/test.ps1`）。
6. 时序常量一律帧；数值改 `data/**/*.json`（三段式键名），禁发表格。

## 5. 顺序（建议 2 周，按里程碑交）

```
M1  shelter 出生 + HUD 上屏 + 吃喝可用          → 能在屋里活着
M2  总览图出门 → 超市灰盒 → 搜刮 + 1 种丧尸战斗  → 能出门一趟
M3  回屋投料/研发/造陷阱 → 跳夜 → 05:00 自动存档 → 一天闭环
M4  死亡重开（当日清晨，同种子一致）             → 能死能重来
M5  第 7 天 20:00 门锁 → 过渡夜 → 阶段 B 七夜波次 → 通关画面 → 【交老板】
```

每个里程碑跑一次 `test.ps1` 并提交；M5 交付后老板进灰盒手感闸门。
